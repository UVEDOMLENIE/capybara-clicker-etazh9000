Полностью переписан фронт под телефон (iPhone-first), но и на компе красиво. Закрыта необработанная обратка владельца (кончались токены) + накопленный фидбек.

🚧 РОАДМАП — ОТ ЭТОГО МЕСТА ПРОДОЛЖАТЬ

Это не общий список «было бы прикольно» — это конкретные спецификации, написанные с расчётом «новый Девин загрузил вкладку и сразу продолжает». Пункты упорядочены по импакту на game-feel: верх — обязательно, низ — наварик.

0. 🚨 БАГИ ОТ РЕАЛЬНЫХ ЮЗЕРОВ (тестер Слава, 10.05.2026)

Жалоба 1: «нестабильно кликает, делает короткие паузы».
Жалоба 2: «двумя пальцами по очереди — случаются разрывы и сбивается ритм».

Анализ:

  • Input lag на бёрстах: doClick() на каждом клике дёргает updateUI(), который пересобирает DOM через innerHTML='' в renderWorkers() и renderAchievements(). При 10+ кликов/сек = layout/repaint storm.
  • Double-tap-zoom delay: слушаем только click — браузер ждёт ~300мс на возможный double-tap.
  • Multi-touch gestures: нет touch-action: manipulation → второй палец = pinch-zoom, не клик.
  • Audio overflow: sfxClick() плодит OscillatorNode без кулдауна → audio pipe захлёбывается.
  • DOM-flood: spawnFloatingNumber() без пула — каждый клик = новый <div>.

Фиксы (по убыванию импакта):

  1. Убрать updateUI() из doClick(). Цикл tick() и так зовёт его 60 раз/сек — больше не нужно. (1-строчный фикс, 70% бага)
  2. В capybaraBtn заменить 'click' → 'pointerdown'. Работает и на мыши, и на тачах, без 300мс задержки.
  3. В style.css к .capybara-btn: touch-action: manipulation; user-select: none;
  4. В sfxClick добавить throttle: глобальная переменная let lastClickSfx = 0, if (Date.now() - lastClickSfx < 30) return; lastClickSfx = Date.now();
  5. В spawnFloatingNumber ограничить пул: если в floatingNumbers.children.length > 30 — удалять старейшие.
  6. На капибару повесить contextmenu/preventDefault уже есть, добавить ещё 'gesturestart' для iOS Safari.
  7. (Опц.) renderWorkers()/renderAchievements() — переписать с diff-обновлением вместо innerHTML clear: хранить ref на DOM-узлы, менять только textContent.

Чексы после фикса: кликать ~150 раз/сек двумя пальцами — должно регистрироваться без потерь, FPS не должен падать ниже 50, плавающие числа должны успевать летать.

1. 🦾 Автолапка + Click Frenzy + Падающие коины

Зачем: чистый кликер скучный, без активности между эвентами игрок засыпает.

Что делать:

  • Автолапка — 5 уровней апгрейда в табе ЛАПКА: auto1 750 КК → +1 авто-клик/сек, auto2 25к → +2, auto3 700к → +4, auto4 2.5М → +8, auto5 1.2Б → +20. В S.autoClickRate, в tick() прибавлять S.autoClickRate * dt * clickValue() к coins, периодически вызывать spawnFloatingNumber() над капибарой.
  • Click Frenzy — отдельный frenzyLoop() запускающий баф каждые 60-180 сек. При активном бафе clickValue() возвращает base * 10, экран багровеет (CSS-фильтр red-frenzy на body), 15 сек. S.frenzyEnd = Date.now() + 15000.
  • Падающие коины — на стейдже периодически (8-15 сек) спавнятся летящие 🪙 / 🍜 / ☕ / 💎 — кликнул → +totalCps()*30, бубль-эффект, sfxCoin(). Не успел поймать — пропадает за 3 сек.

Файлы: game.js (новые upgrade entries в CLICK_UPGRADES, новые функции frenzyLoop, spawnCollectible), style.css (анимации fall-coin, red-frenzy), index.html (<div id="collectibles-layer"></div> внутри .stage).

2. 🎧 DJ-сессия — замедлить ноты

Симптом: ноты падают за 1.5 сек, окно попадания ~0.45 сек — нечитаемо без музыки.

Что делать: в startDjEvent():

  • const FALL_TIME = 1500 → 2500
  • Hit window: laneHeight - KEY_HEIGHT - 60 → - 100
  • Добавить «метроном»: div.dj-metronome пульсирует на каждом 4-м такте
  • Уменьшить частоту спавна нот: rand(380, 700) → rand(550, 900)

3. ⚖️ Баланс ранних апгрейдов

Симптом: ценники в лямах при базовом клике =1, прогресс растягивается на часы.

Что делать в game.js:

  • Капибара-джун: base: 15 → 10
  • Кофеварка-3000: base: 100 → 60
  • Когтистая лапка: cost: 200 → 80
  • Молот тимлида: cost: 4500 → 2200
  • Множитель прироста при purchase: 1.18 → 1.15 (мягче)
  • Оффлайн-гейн: 0.4 → 0.55

Цель: первый престиж за 5-10 минут активной игры (сейчас часы).

🌟 BONUS IDEAS — что Девин надумал сам

Это идеи, которые родились у Девина после анализа фидбека тестера Славы — не прямые исправления, а креативные допилы поверх, превращающие проблемы в фичи. Не обязательны, но сделают игру жирнее.

0.5. 🩹 Мгновенный визуальный отклик на каждый клик

Зачем: психологически решает «нестабильно кликает» ДО любого фикса перфоманса. Сейчас капибара дёргается только на каждом 25-м клике (combo), на промежуточных — никакой реакции.

Что сделать: в doClick() добавить:

capybaraSvg.style.transform = 'scale(0.96)';
setTimeout(() => capybaraSvg.style.transform = '', 60);

Или через CSS-класс .click-pulse с transition: transform 60ms — чище.

Бюджет: 1 строка JS + 3 строки CSS. Импакт огромный.

1. 🤡 Фейк-античит как фича (привет, Слава!)

Зачем: Слава пошутил «капибара не даёт читерить» — обыграть это в честный лор-момент.

Что сделать: добавить трекер recentClicks (последние 1.5 сек). При recentClicks > 18 (~12 клик/сек) запускается мини-эвент:

  1. Капибара говорит «🚨 ОБНАРУЖЕНА ЧИТ-АТАКА! 🚨», экран мигает красным.
  2. На 1.5 сек блокируется доход, кнопка реагирует на клик «лол не работает».
  3. Через 2 сек: «...шучу. +50% мощи на 10 сек, держи 🦫».
  4. S.multiplier *= 1.5 на 10 сек, потом откат.

Срабатывает не чаще 1 раза в 90 сек чтоб не задолбало.

Файлы: game.js (новая функция antiCheatGag() + хук в doClick), CSS красный glitch-overlay.

2. 📊 Счётчик «КЛИКОВ/СЕК» в шапке

Зачем: мотивирует спамить, добавляет соревновательный feel «сколько ты можешь выжать».

Что сделать: новый блок .stat в топбаре после КК/СЕК. Считаем S.recentClicks в скользящем окне 1.5 сек, делим — показываем «КПС». Цвет лейбла:

  • 0–4 кпс — серый
  • 5–9 — зелёный
  • 10–14 — жёлтый
  • 15+ — радужный (rainbow class)

Файлы: index.html + game.js в updateUI.

3. 🦫 Мини-капибара выскакивает из угла

Зачем: дешёвая альтернатива «падающим коинам» из P1, проще в реализации, эффект «нашёл — рад».

Что сделать: отдельный таймер каждые 2-4 минуты:

  • В случайном углу .stage на 2 сек появляется крошечная 🦫 (~28px).
  • Кликнул → +totalCps()*60, sfxAch(), баббл «нашёл стажёра!».
  • Не успел — пропадает молча.

Файлы: только game.js (новая функция spawnMiniCapybara()) + 1 CSS-анимация на bounce-in.

4. 🎵 Клик-как-музыка на бёрстах

Зачем: превратить спам-клик в эмоциональный момент, наградить терпение.

Что сделать: в sfxClick():

  • Если S.recentClicks > 8 (т.е. кпс > ~5): каждый клик играет ноту из мажорной гаммы по кругу: [523, 587, 659, 784, 880, 1047] (C5, D5, E5, G5, A5, C6).
  • Иначе — текущий рандом-сквик.
  • Громкость на бёрсте чуть тише (vol 0.04 вместо 0.06) чтоб не задолбать.

Получается мажорная пентатоника = всегда красиво, какую бы скорость ни выбрал.

5. 🔧 Debug/cheat URL-параметры

Зачем: ускоряет разработку (можно мгновенно проверить эндгейм) + добавляет ещё один пасхалочный слой.

Что сделать: в init() читаем location.search:

  • ?debug=1 — рисуется фиксированный блок снизу-справа: FPS (rolling avg), click-rate, S.coins, S.combo, активный эвент.
  • ?cheat=1 — мгновенно S.coins += 1e9, S.totalCoins += 1e9, но открывается невидимое до этого достижение «🤡 Я ЧИТЕР» которое перманентно даёт -50% к награде. (Шутка-наказание за чит — бан-эффектом, но игра не ломается.)
  • ?reset=1 — очистить localStorage, useful для QA.

Все параметры подсветить в секции пасхалок вики.

Архитектурные решения

  • Без сборщика. Open the page → it runs. No npm, no Webpack, no Vite. Это принципиально — игра должна быть однофайловым деплоем (статика).
  • Vanilla JS, no framework. Никакого React/Vue/Svelte. Render-функции пишут innerHTML или ссылки $(...). Если станет >2000 строк — мигрировать на Preact, не раньше.
  • State в одном объекте S. Сохраняется в localStorage ключом DEVIN_MEGA_CAPYBARA_v1. При load-е делается {...DEFAULT_STATE(), ...saved} — это даёт автоматическую миграцию для новых полей.
  • Game loop через rAF. tick() вызывается ~60 fps, считает dt и применяет CPS. Тяжёлые рендеры (renderWorkers/renderAchievements) ограничены _lastHeavyRender > 400мс.
  • Web Audio API напрямую. Нет ассетов: каждый звук синтезируется через OscillatorNode в функции beep(). P0 fix v0.3.0: throttle 30мс на sfxClickThrottled, чтобы pipeline не захлёбывался на бёрстах.
  • Капибара — SVG inline. В renderCapybaraSvg() склеиваем шаблон из 5×4×4 = 80 комбо. На каждом ~7-м клике вызывается randomizeSkin() (если не S.lockedSkin).
  • Лидерборд локальный (top-10). При первом заходе сидируется 8 синтетических соседей через seedLB(). Серверный — заплеймет позже (FastAPI + Fly.io).
  • Эвенты — свой sub-режим. Когда eventState.active — клики по основной капибаре игнорируются. Каждый эвент сам контролирует свой DOM в #event-area, по завершении вызывает endEvent(reward, label).

Где искать что (быстрый индекс по game.js)

  • VERSION — строка, читается в footer. Меняй при релизе.
  • DEFAULT_STATE() — структура игрового состояния. Новые поля сюда.
  • SKIN_BODY / SKIN_HAT / SKIN_FACE — массивы скинов.
  • WORKERS / CLICK_UPGRADES / ULTRA_UPGRADES — экономика.
  • ACHIEVEMENTS — ачивки с check() (проверяются каждый кадр).
  • SPEECH / MOTIVATIONAL — пуллы реплик.
  • EVENTS — список эвент-id; реализация каждого — отдельная start*Event(banner, area).
  • doClick(x, y) — единственный путь регистрации клика. Сюда подвязано всё (рандомизация скина, мотиватор, чит-детектор).
  • tick() — game loop, вызывается через rAF.
  • init() — стартовая последовательность, прокидывает обработчики.

Что НЕ ломать без причины

  • Ключ DEVIN_MEGA_CAPYBARA_v1 — не переименовывать без миграции, юзеры потеряют прогресс.
  • В doClick() не зови updateUI() — это P0 фикс. UI обновляется в tick().
  • touch-action: manipulation на .capybara-btn — критично для mobile.
  • e.preventDefault() на pointerdown — без него на iOS будет double-fire с click.
  • Throttle sfxClickThrottled — не убирай, audio-pipeline начнёт шипеть.
